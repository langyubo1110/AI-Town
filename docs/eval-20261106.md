## 0. 复现方式


评测前请**停掉 worker**，否则后台仍在写记忆，结果不可复现。

## 1. 检索质量

测试集 **22** 条人工用例，取 Top-5。
记忆池固定 20 条，写入时间跨度 12h ~ 900h（按用例里的 `age_hours` 回拨）。

| 配置 | 权重 (rel / rec / imp) | 半衰期 | Hit@5 | MRR |
| --- | --- | --- | --- | --- |
| `pure_vector` | 1.0 / 0.0 / 0.0 | 138h | 1.000 | 0.901 |
| `with_recency` | 0.6 / 0.4 / 0.0 | 138h | 0.364 | 0.327 |
| `with_importance` | 0.6 / 0.0 / 0.4 | 138h | 0.864 | 0.697 |
| `full_138h` | 0.5 / 0.3 / 0.2 | 138h | 0.364 | 0.327 |
| `importance_heavy` | 0.3 / 0.3 / 0.4 | 138h | 0.409 | 0.277 |
| `gentle_recency` | 0.85 / 0.05 / 0.1 | 138h | 1.000 | 0.947 |
| `long_half_life` | 0.5 / 0.3 / 0.2 | 720h | 0.773 | 0.487 |

**结论**：
- 基线（纯向量）Hit@5 1.000 / MRR 0.901
- 调参后（`gentle_recency`）Hit@5 1.000 / MRR 0.947，相对基线 MRR +0.045
- 最差配置是 `with_recency`（Hit@5 0.364）：**recency 权重过大时，新近度会彻底盖过相关性**
- 因此把线上默认权重改为 **0.85 / 0.05 / 0.10**（`app/memory/ranking.py`），让 recency 只做同等相关度时的轻微偏好

## 3. 端到端性能

> 一次 `/api/chat` = 2 次 LLM（生成回复 + 回合分析）+ 2 次 embedding（写记忆 + 召回 query），所以 P50 在 3.5 秒量级。
> 优化方向：回合分析和回复生成可以并行（分析不依赖回复），预计能压到 2 秒级。

## 4. 已知问题

1. **自评偏差**：judge 与被测模型相同，persona 满分不代表真的没问题。
2. **测试集规模小**：22 条检索用例、10 个对话场景，只能看相对趋势。
3. **检索池只有 20 条**：Top-5 覆盖了 25% 的池子，Hit@5 存在天花板效应；数据量上去后分数一定下降。
4. **单机单用户**：延迟数据不含并发，worker 串行处理（吞吐=1）。
5. **评测与训练同源**：用例内容就是记忆原文的改写，比真实对话简单。
