# 研发规范

## 分支与提交

`main` 分支受保护，任何人都不能直接 push。所有改动走 `feature/xxx` 或 `fix/xxx` 分支，
提 PR 合并。一个 PR 只做一件事，超过 400 行的 PR 会被打回要求拆分。

提交信息用「类型: 说明」格式，类型只能是 feat / fix / docs / refactor / test / chore。

## 代码评审

每个 PR 至少需要 1 位同事 approve 才能合并。评审人应在 48 小时内响应，
超过 48 小时未响应的 PR 可以找 tech lead 指派其他人。

评审关注三件事：逻辑是否正确、有没有测试、命名和注释能不能让人看懂。
不评审代码风格细节——那是 lint 的活。

## 发布窗口

常规发布固定在每周二和周四的 14:00 到 16:00。其他时间不发布，
避免下班前出问题没人处理。

紧急修复（线上故障）可以突破窗口，但必须 tech lead 在群里明确同意，
并且发布后 30 分钟内盯监控。

## 工号规则

工号由入职年份加 4 位序号组成，前缀是字母 A。
例如 2023 年第 17 位入职的员工，工号是 A2023017。

工号用于门禁、报销、内部系统登录。忘记工号可以问 HR 或在 IT 门户查询。

## 值班

研发团队每周轮一人值班，负责处理线上告警。值班表在飞书文档里，
周一早上更新。值班期间手机保持畅通，告警 15 分钟内必须响应。
